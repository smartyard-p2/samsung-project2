## 담당

- 담당자: 이주연, 최인영, 김현수
- 작업 브랜치: `eda`
- 현재 상태: 프로젝트 주제와 데이터셋 선정 중

## 목표

원본 데이터의 구조와 품질을 확인하고, 분석 결과에 근거해 모델 학습에 사용할 데이터를 만든다. 그래프를 만드는 데서 끝내지 않고 발견한 내용과 전처리 판단의 이유를 기록한다.

## 현재 단계에서 할 일

주제와 데이터가 확정되기 전에는 다음 기준으로 후보 데이터를 함께 검토한다.

- 데이터 출처와 라이선스
- 실제 데이터 또는 합성 데이터 여부
- 데이터 크기와 파일 형식
- 타깃 컬럼과 클래스 구성
- 결측치, 이상치, 중복 가능성
- 클래스 불균형 정도
- 데이터 누수 가능성
- 조원 전공 및 프로젝트 주제와의 연관성
- 웹에서 보여줄 만한 분석 결과가 있는지

검토 결과는 데이터셋별 장점, 단점, 예상 작업량과 함께 기록한다.

## 주제 확정 후 할 일

### 데이터 이해 및 품질 확인

- 데이터 크기, 컬럼, 자료형 확인
- 각 컬럼의 의미와 단위 정리
- 결측치, 중복, 이상치 확인
- 타깃 분포와 클래스 불균형 확인
- 학습에 사용하면 안 되는 식별자와 누수 컬럼 확인

### 탐색적 데이터 분석

- 주요 변수의 분포 비교
- 변수 간 관계와 상관관계 분석
- 정상·이상 또는 클래스별 차이 분석
- 시간 순서가 있다면 시계열 변화 분석
- 모델링과 웹에 사용할 핵심 그래프 선정
- 각 그래프에서 알 수 있는 내용을 문장으로 기록

### 전처리

- 불필요한 컬럼 제거
- 결측치와 이상치 처리 기준 수립
- 범주형 변수 인코딩
- 스케일링 필요 여부 판단
- 학습에 필요한 특징 생성
- 학습·검증·테스트 데이터 분리
- 동일한 결과를 다시 만들 수 있는 전처리 코드 작성

## 팀 내부 작업 원칙

- 세부 담당은 데이터가 확정된 뒤 정한다.
- 한 개의 노트북을 여러 명이 동시에 수정하지 않는다.
- 개인별 노트북 또는 파일명을 구분한다.
- 공통 전처리 코드는 담당자를 정한 뒤 한 명이 관리한다.
- 분석 결과에는 그래프뿐 아니라 해석과 판단 근거를 포함한다.
- 모델 결과가 나온 뒤 오분류 데이터를 다시 분석한다.

## 모델링팀에 전달할 것

- 전처리된 학습·검증·테스트 데이터
- 타깃 컬럼명과 클래스 의미
- 입력 변수 목록과 순서
- 제거한 컬럼과 제거 이유
- 전처리 단계와 사용한 기준
- 데이터 누수 및 클래스 불균형 점검 결과
- 전처리 코드를 실행하는 방법

## 웹 담당자에게 전달할 것

- 웹에 표시할 핵심 차트
- 차트 생성 코드 또는 차트용 데이터
- 차트 제목, 축 이름과 단위
- 차트별 핵심 해석 문장
- 전처리 전후 데이터 규모와 요약 통계

## 저장 위치

| 내용 | 경로 | 파일명 규칙 |
|---|---|---|
| 개인 EDA 노트북 | `notebooks/` | `01_eda_<이름>.ipynb` — **1인 1파일**, 공동 편집 금지 |
| 재사용 전처리 코드 | `src/` | `preprocess.py` 등 (담당자 1명이 관리) |
| 전처리 중간 결과 | `data/interim/` | Git에 올리지 않음 |
| 최종 학습용 데이터 | `data/processed/` | Git에 올리지 않음 |
| 그래프 이미지 | `reports/figures/` | `<주제>_<내용>.png` |
| 데이터 출처 기록 | `data/README.md` | 표에 추가 |

원본 데이터는 `data/raw/`에 두고 **절대 수정하지 않는다.**

## 예상 산출물

- 데이터 품질 점검 결과
- 개인별 EDA 노트북 또는 분석 코드
- 재실행 가능한 전처리 코드
- 전처리된 데이터
- 컬럼 및 데이터 설명서
- 웹과 발표에 사용할 핵심 그래프와 해석

구체적인 파일명과 저장 위치는 주제와 데이터가 확정된 뒤 이 문서에 추가한다.

## 완료 기준

- 원본 데이터의 구조와 문제점을 설명할 수 있다.
- 모든 주요 전처리 결정에 이유가 기록되어 있다.
- 원본 데이터에서 최종 데이터를 다시 생성할 수 있다.
- 학습·검증·테스트 데이터 사이에 누수가 없다.
- 모델링팀이 별도 수정 없이 결과 데이터를 사용할 수 있다.
- 핵심 그래프의 의미를 담당자가 직접 설명할 수 있다.
- 모델 오분류 결과에 대한 추가 분석이 포함되어 있다.

## Git 작업 규칙

1. 작업 전 `eda` 브랜치의 최신 내용을 Pull한다.
2. 본인에게 지정된 파일만 수정한다.
3. 원본 대용량 데이터는 Git에 직접 올리지 않는다.
4. 개인 PC의 절대경로를 코드에 작성하지 않는다.
5. 노트북은 위에서 아래로 다시 실행되는지 확인한다.
6. 작업 단위별로 Commit하고 내용을 명확하게 작성한다.
7. 다른 팀이 사용할 수 있는 결과가 완성되면 `main` 병합용 Pull Request를 생성한다.

전체 명령어와 문제 해결 방법은 [`docs/GIT_GUIDE.md`](../GIT_GUIDE.md)에 있다.
특히 **매일 아침 `main` 동기화**([4번 항목](../GIT_GUIDE.md#4-main의-최신-내용-내려받기-매일-1회))를 빠뜨리지 않는다.
