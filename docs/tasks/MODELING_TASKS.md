## 목표

선정한 문제에 적합한 기준 모델을 만들고, 실험을 통해 개선한 뒤 결과를 객관적으로 평가한다. 최종 모델은 웹에서 호출할 수 있는 형태로 제공한다.

## 현재 단계에서 할 일

주제와 데이터가 확정되기 전에는 후보 데이터마다 다음 내용을 검토한다.

- 해결할 문제가 분류, 군집 또는 강화학습 중 무엇인지
- 예측 또는 분석할 목표가 명확한지
- 사용할 수 있는 입력 변수가 충분한지
- 타깃 클래스의 수와 불균형 정도
- 적절한 평가 지표
- 예상 가능한 기준 모델과 개선 모델
- 제한된 기간에 학습과 평가가 가능한 데이터 크기인지
- 웹에서 예측 과정을 시연할 수 있는지

## 주제 확정 후 할 일

### 기준 모델

- 단순한 모델을 먼저 학습해 기준 성능 확보
- 학습·검증·테스트 데이터 분리 방식 확인
- 동일한 조건에서 비교할 평가 지표 결정
- 실험 조건과 난수값 기록

### 모델 개선

- 여러 후보 모델의 성능 비교
- 하이퍼파라미터 조정
- 클래스 불균형 처리 필요성 검토
- 특징 선택 또는 특징 중요도 분석
- 과적합 여부 확인
- 개선 전후 결과 비교

### 평가와 해석

- 정확도 외에 문제에 적합한 지표 사용
- 혼동행렬 확인
- 클래스별 정밀도, 재현율 및 F1 점수 확인
- 고장을 놓친 경우와 오경보 사례를 구분해 분석
- 오분류 데이터를 EDA팀에 전달해 추가 분석 요청
- 모델의 한계와 실제 적용 시 주의점 기록

### 웹 연동 준비

- 전처리부터 예측까지 동일하게 적용되는 함수 제공
- 모델 저장 및 불러오기 방법 작성
- 입력 컬럼명, 순서, 자료형 명시
- 예측값과 확률 등 출력 형식 명시
- 정상 입력과 잘못된 입력 예시 작성

## 팀 내부 작업 원칙

- 기준 모델과 개선 모델의 담당은 데이터가 확정된 뒤 정한다.
- 모델 간 비교는 같은 데이터 분할과 평가 지표를 사용한다.
- 테스트 데이터는 최종 평가 전까지 모델 개선에 사용하지 않는다.
- 결과가 좋은 실험만 남기지 않고 주요 실험 조건과 결과를 기록한다.
- 모델 성능 수치는 실행 코드에서 다시 확인할 수 있어야 한다.

## EDA·전처리팀으로부터 받을 것

- 전처리된 학습·검증·테스트 데이터
- 타깃 컬럼과 클래스 의미
- 입력 변수 목록과 순서
- 전처리 방법 및 제거된 컬럼
- 클래스 불균형과 데이터 누수 점검 결과

## 웹 담당자에게 전달할 것

- 저장된 최종 모델
- 모델을 불러오는 코드
- 호출 가능한 예측 함수
- 입력 스키마와 입력 예시
- 출력 스키마와 출력 예시
- 최종 성능 지표와 혼동행렬 데이터
- 모델이 처리할 수 없는 입력 조건

예측 함수의 기본 형태는 주제 확정 후 웹 담당자와 협의한다.

```python
result = predict(input_data)
```

## 저장 위치

| 내용 | 경로 | 파일명 규칙 |
|---|---|---|
| 실험 노트북 | `notebooks/` | `02_model_<이름>.ipynb` — **1인 1파일**, 공동 편집 금지 |
| 재사용 모델 코드 | `src/` | `train.py`, `predict.py` 등 |
| 학습된 모델·전처리 객체 | `models/` | `<모델>_<버전>.pkl` — Git에 올리지 않음 |
| 모델 성능 기록 | `models/README.md` | 표에 추가 |
| 평가 그래프 | `reports/figures/` | `<모델>_<내용>.png` |

모델을 저장할 때 **전처리 객체를 반드시 함께 저장한다.**

## 예상 산출물

- 기준 모델 학습 코드
- 모델별 실험 및 비교 결과
- 최종 모델 학습 코드
- 저장된 모델과 필요한 전처리 객체
- 평가 지표와 혼동행렬
- 오분류 분석 결과
- 웹에서 사용할 예측 함수와 입출력 설명서

구체적인 파일명과 저장 위치는 주제와 데이터가 확정된 뒤 이 문서에 추가한다.

## 완료 기준

- 기준 모델과 최종 모델의 성능 차이를 설명할 수 있다.
- 데이터 분리와 평가 방법이 기록되어 있다.
- 테스트 데이터로 최종 성능을 확인했다.
- 실행할 때마다 같은 조건에서 결과를 재현할 수 있다.
- 저장된 모델을 새 프로세스에서 불러와 예측할 수 있다.
- 웹 담당자가 모델 내부 코드를 수정하지 않고 예측 함수를 호출할 수 있다.
- 오분류 사례와 모델의 한계를 설명할 수 있다.

## Git 작업 규칙

1. 작업 전 `modeling` 브랜치의 최신 내용을 Pull한다.
2. 본인에게 지정된 파일만 수정한다.
3. 대용량 모델 파일은 올리기 전에 저장 방식과 용량을 조장과 확인한다.
4. 개인 PC의 절대경로를 코드에 작성하지 않는다.
5. 실험 결과와 주요 설정을 함께 기록한다.
6. 작업 단위별로 Commit하고 내용을 명확하게 작성한다.
7. 다른 팀이 사용할 수 있는 결과가 완성되면 `main` 병합용 Pull Request를 생성한다.

전체 명령어와 문제 해결 방법은 [`docs/GIT_GUIDE.md`](../GIT_GUIDE.md)에 있다.
특히 **매일 아침 `main` 동기화**([4번 항목](../GIT_GUIDE.md#4-main의-최신-내용-내려받기-매일-1회))를 빠뜨리지 않는다.
