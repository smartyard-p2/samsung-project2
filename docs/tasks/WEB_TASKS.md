## 담당

- 담당자: 조장
- 작업 브랜치: `web`
- 현재 상태: 프로젝트 주제와 데이터셋 선정 중

## 목표

분석 결과와 모델 예측 결과를 사용자가 이해하기 쉬운 웹 화면으로 제공한다. 프론트엔드와 백엔드는 같은 `web` 브랜치에서 관리한다.

## 현재 단계에서 할 일

주제와 데이터가 확정되기 전에는 프레임워크나 화면 구조를 확정하지 않는다. 다음 항목만 후보별로 검토한다.

- 사용자가 웹에서 확인해야 할 핵심 정보
- 사용자가 직접 입력할 값과 예측 결과
- EDA 결과 중 웹에 표시할 차트
- 모델링팀으로부터 받아야 할 입력·출력 형식
- 발표 환경에서 인터넷 없이 시연할 수 있는 방법

## 주제 확정 후 할 일

### 프론트엔드

- 핵심 화면과 사용자 흐름 정의
- 데이터 개요와 EDA 결과 시각화
- 모델 예측 입력 화면 구현
- 예측 결과와 해석 화면 구현
- 오류, 로딩, 빈 데이터 상태 처리

### 백엔드

- 데이터 조회 API 구현
- 모델 예측 API 구현
- 요청값 검증과 오류 응답 처리
- 모델 파일 로딩 및 예측 함수 연결
- DB 및 데이터 파이프라인 연동

## 협업 시 필요한 입력

### EDA·전처리팀으로부터 받을 것

- 최종 컬럼명과 각 컬럼의 의미
- 웹에 사용할 차트 데이터 또는 차트 생성 코드
- 전처리된 데이터의 위치와 형식
- 그래프별 해석 문장

### 모델링팀으로부터 받을 것

- 저장된 최종 모델
- 모델 입력 컬럼과 순서
- 입력 예시와 출력 예시
- 호출 가능한 예측 함수
- 성능 지표와 혼동행렬 등 평가 결과

## 저장 위치

| 내용 | 경로 |
|---|---|
| 프론트엔드 | `front/` |
| 백엔드 | `backend/` |
| 환경변수 예시 | `.env.example` (실제 `.env`는 커밋하지 않음) |

모델 파일은 `models/`, 데이터는 `data/`에서 읽는다. 경로는 **환경변수 또는 상대경로**로 처리하고 개인 PC 절대경로를 쓰지 않는다.

## 예상 산출물

- `front/`: 사용자 화면
- `backend/`: API와 모델 연결
- API 요청·응답 명세
- 로컬 실행 방법
- 배포 및 발표 시연 방법

구체적인 파일 구조와 기술 스택은 주제와 데이터가 확정된 뒤 이 문서에 추가한다.

## 완료 기준

- 새로운 환경에서 안내 문서대로 실행할 수 있다.
- 프론트엔드가 백엔드 API를 통해 데이터를 가져온다.
- 사용자가 입력값을 보내고 실제 모델의 예측 결과를 확인할 수 있다.
- EDA와 모델 평가 결과가 웹 화면에 표시된다.
- 잘못된 입력이나 API 오류가 화면에서 처리된다.
- 발표용 시연 시나리오가 준비되어 있다.

## Git 작업 규칙

1. 작업 전 `web` 브랜치의 최신 내용을 Pull한다.
2. 프론트엔드는 `front/`, 백엔드는 `backend/`에서 작업한다.
3. API 키, 비밀번호, 환경변수 파일은 커밋하지 않는다.
4. 실행 가능한 단위로 Commit하고 내용을 명확하게 작성한다.
5. 안정적으로 동작하는 기능 단위가 완성되면 `main` 병합용 Pull Request를 생성한다.

전체 명령어와 문제 해결 방법은 [`docs/GIT_GUIDE.md`](../GIT_GUIDE.md)에 있다.
특히 **매일 아침 `main` 동기화**([4번 항목](../GIT_GUIDE.md#4-main의-최신-내용-내려받기-매일-1회))를 빠뜨리지 않는다.
