## 담당

- 담당자: 조장
- 작업 브랜치: `data-infra`
- 현재 상태: 프로젝트 주제와 데이터셋 선정 중

## 목표

모든 조원이 같은 데이터를 같은 방법으로 사용할 수 있도록 데이터 수집, 저장, 버전 관리와 실행 환경을 구성한다. 웹과 모델이 필요한 데이터를 안정적으로 받을 수 있게 한다.

## 현재 단계에서 할 일

주제와 데이터가 확정되기 전에는 실제 아키텍처나 DB를 구현하지 않는다. 후보 데이터마다 다음 항목을 검토한다.

- 공식 데이터 출처와 다운로드 방식
- 라이선스와 재배포 가능 여부
- 파일 크기와 GitHub 업로드 제한
- 파일 형식과 압축 해제 방식
- 데이터 갱신 여부
- 원본·중간·최종 데이터의 예상 크기
- DB 사용이 실제로 필요한지
- 로컬 실행과 배포 환경에서 데이터를 제공할 방법
- 개인정보나 민감정보 포함 여부

## 주제 확정 후 할 일

### 데이터 수집 및 관리

- 공식 출처에서 원본 데이터를 내려받는 방법 작성
- 원본 데이터 변경 없이 보관
- 원본, 중간 결과, 최종 데이터를 구분
- 데이터 버전과 생성 날짜 기록
- 대용량 데이터와 생성 파일에 대한 `.gitignore` 관리

### 데이터 파이프라인

- 원본 데이터 수집 또는 적재 단계 구성
- EDA·전처리팀의 전처리 코드 연결
- 전처리 결과 저장
- 모델 학습용 데이터 제공
- 웹 또는 DB 적재 단계 연결
- 실패 시 원인을 확인할 수 있는 로그 구성

### DB

- 웹 기능에 DB가 필요한지 먼저 판단
- 필요한 경우 테이블과 관계 설계
- 원본 데이터와 서비스용 데이터를 구분
- 중복 적재 방지
- 초기화 및 샘플 데이터 적재 방법 작성
- 접속 정보와 비밀번호를 환경변수로 관리

### 실행 및 배포 환경

- Python 및 주요 런타임 버전 고정
- 의존성 설치 방법 제공
- 환경변수 예시 파일 제공
- 로컬 실행 절차 정리
- 웹, API, DB 배포 방식 구성
- 발표 전 백업 시연 방법 준비

## 협업 시 제공할 것

### EDA·전처리팀에 제공

- 원본 데이터 위치와 다운로드 방법
- 데이터 사용 규칙
- 결과 데이터를 저장할 위치와 이름 규칙
- 실행 환경과 필요한 의존성

### 모델링팀에 제공

- 전처리된 데이터 위치와 버전
- 학습 결과 및 모델 파일 저장 규칙
- 공통 실행 환경

### 웹에 제공

- DB 연결 방법 또는 데이터 조회 방법
- 서비스용 데이터 형식
- 환경변수 목록
- 배포 환경에서 사용할 설정

## 저장 위치

| 내용 | 경로 |
|---|---|
| 데이터 폴더 구조·출처 기록 | `data/`, `data/README.md` |
| 수집·적재 스크립트 | `src/` |
| 환경변수 예시 | `.env.example` |
| Python 의존성 | `requirements.txt` |
| 실행·설치 방법 | `README.md` |

데이터 파일 본체는 Git이 아니라 **팀 공유 드라이브**로 주고받는다.

## 예상 산출물

- 데이터 다운로드 또는 적재 스크립트
- 데이터 디렉터리 및 버전 관리 규칙
- 전처리·학습·적재 파이프라인
- 필요한 경우 DB 스키마와 초기화 코드
- 공통 실행 환경과 의존성 파일
- 환경변수 예시 파일
- 로컬 실행 및 배포 문서

구체적인 아키텍처, DB 종류와 배포 방식은 주제와 데이터가 확정된 뒤 이 문서에 추가한다.

## 완료 기준

- 새로운 환경에서 공식 출처로부터 데이터를 준비할 수 있다.
- 원본 데이터에서 모델 학습용 데이터를 다시 생성할 수 있다.
- 모든 팀이 같은 데이터 버전과 컬럼 규격을 사용한다.
- 비밀번호와 API 키가 저장소에 포함되지 않는다.
- 필요한 경우 DB를 초기화하고 데이터를 중복 없이 적재할 수 있다.
- 웹과 모델링 코드가 정해진 경로 또는 인터페이스로 데이터를 사용할 수 있다.
- 배포 환경에서 전체 흐름을 실행할 수 있다.

## Git 작업 규칙

1. 작업 전 `data-infra` 브랜치의 최신 내용을 Pull한다.
2. 원본 데이터와 대용량 생성 파일은 Git에 직접 올리지 않는다.
3. 비밀번호, 인증키와 실제 `.env` 파일은 커밋하지 않는다.
4. 개인 PC의 절대경로 대신 프로젝트 기준 상대경로를 사용한다.
5. 설정이 바뀌면 실행 문서와 예시 환경변수도 함께 수정한다.
6. 작업 단위별로 Commit하고 내용을 명확하게 작성한다.
7. 다른 팀이 사용할 수 있는 결과가 완성되면 `main` 병합용 Pull Request를 생성한다.

전체 명령어와 문제 해결 방법은 [`docs/GIT_GUIDE.md`](../GIT_GUIDE.md)에 있다.
특히 **매일 아침 `main` 동기화**([4번 항목](../GIT_GUIDE.md#4-main의-최신-내용-내려받기-매일-1회))를 빠뜨리지 않는다.
